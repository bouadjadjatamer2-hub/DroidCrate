# مراحل بناء DroidCrate

هذا الملف يوثّق نطاق كل مرحلة وما تم إنجازه. لا ننتقل إلى مرحلة قبل التأكد من أن
التطبيق يشتغل وأن المرحلة السابقة مكتملة.

## المرحلة 0 — تهيئة المشروع

- هيكل Electron + React + TypeScript + Vite.
- الترخيص MIT من أول خطوة.
- واجهة أولية بشريط جانبي: الجهاز، الأدوات، قوائم التحقق، الدروس، السجل، الإعدادات.
- تصميم غامق هادئ، مع دعم العربية RTL عند اختيار العربية.
- ملفات المساهمة والقضايا والتنبيهات القانونية.

## المرحلة 1 — التعرف على الهاتف

- مراقبة USB عبر معرّفات VID/PID.
- التعرّف على ADB وFastboot وDownload Mode وEDL وBROM.
- عرض الماركة والموديل ووضع الاتصال.
- اقتراح الأداة المناسبة ورابطها الرسمي.
- رسالة إرشادية عند عدم التعرّف.

### ما تم إنجازه

- قواعد التعرّف في `data/devices.json` قابلة للتعديل، مع تحقق `zod` عند القراءة.
- فحص ويندوز عبر `Get-PnpDevice` و`DEVPKEY_Device_BusReportedDeviceDesc`، دون
  صلاحيات مدير.
- تجميع واجهات USB التابعة لنفس الهاتف في بطاقة واحدة.
- محدّث تلقائي كل 3 ثوانٍ عبر IPC، مع زر «افحص الآن».
- عرض الثقة في التطابق: قاعدة دقيقة، وضع مستنتج، أو يحتاج مراجعة.
- أزرار الروابط الرسمية للأداة والدرايفر عبر المتصفح الافتراضي فقط.
- واجهة عربية RTL كاملة، واختبارات وحدات للمطابقة.

### التحقق

```powershell
npm test
npm run typecheck
npm run build
node scripts/capture-stage-1.mjs
```

لقطات الشاشة: `docs/screenshots/stage-1-device.png` و
`docs/screenshots/stage-1-device-ar.png`.

### حدود معروفة

- الكشف يعتمد على ما يعرضه ويندوز؛ إذا كان الدرايفر مفقوداً قد يظهر الجهاز
  كـ«غير معروف» أو لا يظهر إطلاقاً.
- لا يتم تنفيذ أوامر ADB أو Fastboot في هذه المرحلة، ولا تُحمَّل أي أدوات.
- أسماء الموديل التي توفرها بعض الشركات قد تكون عامة أو غير متاحة.

## المرحلة 2 — مكتبة الأدوات

- بطاقات الأدوات مع التوافق والصعوبة والدرايفرات والأخطاء الشائعة.
- بحث وفلترة حسب الماركة والشيبسيت ومستوى الصعوبة.
- فتح الروابط الرسمية فقط.

### ما تم إنجازه

- 16 أداة في `data/tools.json`: Platform Tools، Android Flash Tool، Google USB
  Driver، Smart Switch، Odin، Heimdall، SP Flash Tool، QFIL، Mi Flash Tool،
  MSM Download Tool، LGUP، TWRP، OrangeFox، Magisk، KernelSU، APatch.
- مخطط `zod` يمنع تكرار المعرّفات ويمنع وضع رابط تنزيل مباشر لأداة «دعم فقط».
- بحث فوري، وفلترة حسب الفئة والماركة والشيبسيت والصعوبة.
- شارة واضحة لكل أداة: «تنزيل رسمي» أو «دعم فقط»، مع تحذير للمخاطر.
- روابط رسمية فقط تُفتح في المتصفح الافتراضي، ولا تُحمَّل أي أداة داخل التطبيق.
- واجهة عربية RTL مع معالجة النصوص الإنجليزية المختلطة.

### التحقق

```powershell
npm test
npm run build
node scripts/capture-stage-2.mjs
```

اللقطات: `docs/screenshots/stage-2-tools.png`، `stage-2-filter.png`،
`stage-2-tools-ar.png`.

### حدود معروفة

- الأدوات التي لا توفر تنزيلاً عاماً (Odin وQFIL وSP Flash Tool وغيرها) تعرض
  صفحة الدعم الرسمية فقط، وهذا مقصود.
- البحث لا يترجم أسماء الأدوات؛ أسماء المنتجات تبقى بالإنجليزية.

## المرحلة 3 — قوائم التحقق

- قوائم تفاعلية لخمس عمليات خطيرة.
- نقاط إجبارية وأخرى اختيارية مع شرح لكل نقطة.
- تأكيد ملكية الجهاز قبل أي عملية.

### ما تم إنجازه

- خمس قوائم في `data/checklists.json`: استعادة الفيرموير الأصلي، فتح
  البوتلودر، ريكفري مخصص، روت، وروم مخصص.
- 46 خطوة موثّقة، كل خطوة تشرح سببها، مع تمييز «إجباري» و«اختياري».
- بوابة تأكيد ملكية إلزامية قبل فتح أي قائمة، بموافقتين صريحتين.
- لا يمكن إكمال القائمة قبل تحديد كل الخطوات الإجبارية.
- تقدم محفوظ محلياً في `localStorage`، مع إعادة ضبط يدوية.
- شريط تقدم، حالة «مكتملة»، وتاريخ الإكمال.
- مخطط `zod` يضمن تفرد المعرّفات ووجود خطوة إجبارية في كل قائمة.

### التحقق

```powershell
npm test
npm run build
node scripts/capture-stage-3.mjs
```

اللقطات: `docs/screenshots/stage-3-checklists.png`، `stage-3-ownership.png`،
`stage-3-completed.png`، `stage-3-checklists-ar.png`.

### حدود معروفة

- التقدم محلي في المتصفح/التطبيق وليس بعد في SQLite؛ ستُنقل البيانات في مرحلة
  الدروس والسجل.
- نصوص الخطوات بالإنجليزية حالياً، بينما واجهة التحكم كاملة بالعربية والإنجليزية.
- البوابة تمنع الاستعمال غير المسؤول ولا تتحقق تقنياً من ملكية الجهاز.

## المرحلة 4 — أدوات الاتصال

- تنزيل Platform Tools من Google والتحقق من SHA-256.
- أزرار ADB وFastboot بدل الأوامر اليدوية.
- سجل مباشر لكل أمر.
- لا فتح بوتلودر ولا فلاش في هذه المرحلة.

### ما تم إنجازه

- كتالوج مثبّت في `data/platform-tools.json`: الإصدار 37.0.1، الرابط الرسمي من
  `dl.google.com`، الحجم، وSHA-256 وSHA-1. لا يُقبل أي رابط من نطاق آخر.
- تنزيل مع شريط تقدم وإمكانية الإلغاء، وحساب SHA-256 أثناء التنزيل ثم إعادة
  حسابه على الملف المحفوظ قبل فك الضغط.
- فك ضغط آمن يمنع الخروج من مجلد التثبيت، ثم تثبيت ذري في
  `%APPDATA%\droidcrate\platform-tools\current` مع استعادة النسخة السابقة عند الفشل.
- كشف الإصدار المثبّت عبر `adb version` ومقارنته بالكتالوج، مع زر إعادة فحص.
- شاشة «وحدة ADB» جديدة في الشريط الجانبي: حالة التثبيت، الأجهزة المتصلة مع
  الحالة (device / unauthorized / offline)، وFastboot.
- جدول أفعال ثابت في العملية الرئيسية (allow-list): إصدار ADB، معلومات الجهاز،
  البطارية، مساحة `/data`، فحص Fastboot، وقراءة متغيّرات البوتلودر.
- إعادة التشغيل إلى النظام أو البوتلودر أو الريكفري فقط بعد تأكيد صريح داخل
  بوابة الملكية؛ لا يوجد أي أمر حر أو `shell` مفتوح.
- سجل أوامر محلي يعرض الزمن والمدة والخرج، مع تقييد حجم الخرج وتفريغ يدوي.
- نصوص إنجليزية وعربية كاملة مع RTL، وتصميم متجاوب، واختبارات للمخطط
  والمحلّلات وقائمة الأفعال المسموحة.

### التحقق

```powershell
npm test
npm run typecheck
npm run build
node scripts/capture-stage-4.mjs
```

تم التثبيت الفعلي من داخل التطبيق: نُزّل الأرشيف الرسمي، طابق SHA-256، وفُك
الضغط، وأصبح `adb version` يعرض 37.0.1. نجح أيضاً `adb devices -l` و
`adb shell getprop` على جهاز حقيقي بعد الموافقة على تصحيح USB.

اللقطات: `docs/screenshots/stage-4-install-before.png`، `stage-4-installed.png`،
`stage-4-command-log.png`، `stage-4-device-snapshot.png`، `stage-4-console-ar.png`.

### حدود معروفة

- اسم الأرشيف في كتالوج Google ثابت (`platform-tools-latest-windows.zip`) لكن
  محتواه يتغيّر مع كل إصدار؛ لذلك أي تغيير في البصمة يوقف التثبيت بدل قبول ملف
  غير متحقق. يجب تحديث `data/platform-tools.json` عند صدور إصدار جديد.
- فك الضغط يُختبر داخل Electron؛ أداة `extract-zip` قد تتعطل عند تشغيلها من
  Node وحده، وهذا لا يؤثر على التطبيق.
- الأوامر للقراءة فقط عدا إعادة التشغيل. لا فتح بوتلودر، ولا فلاش، ولا مسح، ولا
  تجاوز حساب في هذه المرحلة.
- إن كان الجهاز `unauthorized` تظهر إرشادات للموافقة على نافذة التصحيح بدل
  تنفيذ الأمر.

## المرحلة 5 — مسار التعلم

- ثلاثة مستويات، دروس Markdown قابلة للتعديل.
- اختبار قصير بعد كل درس.
- حفظ التقدم في SQLite.

### ما تم إنجازه

- تسعة دروس في ثلاثة مستويات: الأساسيات، الصيانة، والإصلاح المتقدم.
- كل درس ملف Markdown مستقل في `data/lessons/`، وكتالوج `data/lessons.json`
  يحدد المستوى والوقت والأسئلة. تعديل ملف نصي يكفي لتحديث الدرس.
- مخطط `zod` يتحقق من المستويات، تفرد المعرّفات، وجود ملف لكل درس، وأن كل إجابة
  تشير إلى خيار موجود.
- ثلاثة أسئلة قصيرة لكل درس مع شرح لكل إجابة، ودرجة نجاح 60% (إجابتان من ثلاث).
- حفظ التقدم في SQLite داخل مجلد بيانات المستخدم: `droidcrate.db`، مع جداول
  `lesson_progress` و`quiz_attempts` و`checklist_progress`.
- أفضل نتيجة وعدد المحاولات لكل درس، وحالة «مكتمل»، وإمكانية إعادة ضبط الدرس.
- ترحيل تلقائي مرة واحدة لتقدم قوائم التحقق من `localStorage` القديم إلى SQLite،
  ثم حذف المفتاح القديم بعد نجاح الاستيراد.
- عرض آمن لـMarkdown عبر `marked` و`DOMPurify`، مع فتح الروابط في المتصفح.
- واجهة كاملة بالإنجليزية والعربية مع RTL، وشريط تقدم لكل مستوى.
- أزرار المستويات تنقل إلى أول درس، وقائمة الدروس تعرض الحالة والوقت وأفضل نتيجة.

### التحقق

```powershell
npm test
npm run typecheck
npm run build
node scripts/capture-stage-5.mjs
```

تم إكمال درس فعلياً (3/3)، ثم إعادة تحميل التطبيق والتأكد من بقاء حالة «مكتمل»
في SQLite. كما تم اختبار ترحيل قائمة تحقق قديمة من `localStorage`: ظهر العنصر
المحدد في الواجهة، وأصبح الصف موجوداً في `checklist_progress`.

اللقطات: `docs/screenshots/stage-5-lessons.png`، `stage-5-quiz.png`،
`stage-5-progress.png`، `stage-5-lessons-ar.png`.

### حدود معروفة

- نصوص الدروس بالإنجليزية لأنها مادة تقنية دقيقة، بينما واجهة التحكم كاملة
  بالعربية. اتجاه نص الدرس يبقى LTR حتى في الوضع العربي لسلامة القوائم والأرقام.
- التقدم محلي فقط ولا تتم مزامنته بين الأجهزة.
- درجة النجاح 60% لتناسب اختبارات من ثلاثة أسئلة؛ يمكن رفعها عند توسيع الأسئلة.
- SQLite يعمل عبر `node:sqlite` المدمج في Electron، فلا حاجة لبناء وحدات أصلية.

## المرحلة 6 — سجل العمليات

- تسجيل التاريخ والجهاز والعملية والنتيجة.
- بحث وفلترة.
- تصدير TXT وCSV.

### ما تم إنجازه

- جدول `operation_history` في نفس قاعدة SQLite، مع فهرس على وقت البدء. كل صف
  يحمل التصنيف (ADB / Fastboot / Platform Tools / قائمة تحقق)، معرّف الإجراء،
  الأمر الحرفي، الرقم التسلسلي إن وُجد، النتيجة، وتفاصيل الخطأ.
- التسجيل تلقائي في العملية الرئيسية: كل أمر ADB أو Fastboot يُنفَّذ يُسجَّل
  بنجاحه أو فشله، وكذلك تثبيت Platform Tools، وإكمال قائمة تحقق لأول مرة.
  تعليم خطوة واحدة لا يُسجَّل حتى لا يمتلئ السجل بضجيج.
- `HistoryService` يعزل القراءة والمسح والتصدير. فشل الكتابة في السجل لا يوقف
  أمر الجهاز؛ التسجيل دائماً أفضل جهد (best effort).
- تصدير TXT وCSV عبر مربع حوار حفظ في النظام. ملف CSV يبدأ بـUTF-8 BOM حتى تظهر
  العربية بشكل صحيح في Excel، ويقتبس الحقول التي تحوي فواصل أو علامات تنصيص أو
  أسطراً جديدة.
- شاشة سجل كاملة: بحث فوري في الأمر والإجراء والجهاز والتفاصيل، فلترة بالتصنيف
  والنتيجة، صفوف قابلة للتوسيع تعرض الإجراء والجهاز والوقت والخطأ، عدّاد محلي،
  ومسح بخطوتين لتجنب الحذف بالخطأ.
- حالات فراغ واضحة: لا سجل بعد، أو لا نتائج مطابقة للفلاتر.
- عربية كاملة مع RTL؛ الطوابع الزمنية تُعرض بأرقام لاتينية داخل عزل LTR حتى لا
  ينقلب ترتيب التاريخ، ونص الأمر يبقى LTR لأنه تقني.

### التحقق

```powershell
npm test
npm run typecheck
npm run build
node scripts/capture-stage-6.mjs
```

تم تنفيذ أمر `adb version` وإكمال قائمة «Restore stock firmware» من الواجهة،
فظهر صفان في السجل. نجح البحث عن `version` في تصفية صف واحد، وفلتر «Checklist»
في تصفية صف واحد أيضاً. تم تصدير CSV عبر مربع حوار مُستبدل في الاختبار: كتب
الملف سطرين بعد الترويسة، وبدأ بعلامة BOM. مجموع الاختبارات: **29 ناجحاً**.

اللقطات: `docs/screenshots/stage-6-history.png`، `stage-6-detail.png`،
`stage-6-filter.png`، `stage-6-export.png`، `stage-6-history-ar.png`.

### حدود معروفة

- الشاشة تعرض آخر 500 عملية؛ الصفوف الأقدم تبقى في القاعدة لكن لا تُعرض بعد أن
  يتجاوز السجل 500 صف. التصدير يستخدم القائمة نفسها.
- المسح نهائي ولا يمكن التراجع عنه، لذلك يتطلب ضغطتين متتاليتين.
- لا يُسجَّل كل خطوة في قائمة التحقق، بل إكمال القائمة فقط.
- السجل محلي بالكامل ولا تتم مزامنته بين الأجهزة.

## المرحلة 7 — التحديث والعمل دون إنترنت

- التطبيق يعمل كاملاً دون شبكة.
- فحص تحديثات البيانات والدروس بموافقة المستخدم.
- التحديث لا يمس التقدم ولا السجل.

## المرحلة 8 — التلميع والإصدار

- اختبارات للتعرّف والقوائم والتحديث.
- إصلاح التحذيرات وتحسين بدء التشغيل.
- مثبّت ويندوز، صفحة الموقع، ونشر GitHub Release.
- شاشة ترحيب وتنبيه قانوني في أول تشغيل.
